<h1> RAG для новостного Telegram канала </h1>

<h2> О проекте </h2>
<p> Проект реализует RAG систему для ответов на вопросы на основе постов из Telegram канала издания РБК </p>


<h2>🔄 Обновление базы документов</h2>
<p>
Пайплайн обновления базы данных отвечает за автоматическое извлечение, обработку и сохранение текстовых данных
для последующего использования в RAG-модели.
</p>

<ol>
  <li>
    <b>Выгрузка постов из Telegram-канала</b><br/>
    Система выгружает новые посты из Telegram-канала при помощи Pyrogram модуля.
  </li>
  <li>
    <b>Фильтрация контента</b><br/>
    Посты очищаются от нерелевантного контента (служебных сообщений, рекламы, пустых или слишком коротких записей).
  </li>
  <li>
    <b>Чанкинг текста</b><br/>
    Отфильтрованный текст разбивается на логические фрагменты (chunks) фиксированного или динамического размера
    для повышения качества векторного поиска.
  </li>
  <li>
    <b>Векторизация и сохранение</b><br/>
    Каждый чанк преобразуется в векторное представление с помощью embedding-модели и сохраняется в
    <b>Qdrant DataBase</b> вместе с метаданными.
  </li>
</ol>

<h2>RAG пайплайн </h2>
<p>
Данный пайплайн используется для генерации ответов на пользовательские запросы с учетом сохраненного контекста.
</p>

<ol>
  <li>
    <b>Запрос пользователя</b><br/>
    Пользователь задает вопрос в произвольной форме.
  </li>
  <li>
    <b>Векторизация запроса</b><br/>
    Вопрос преобразуется в векторное представление с использованием той же embedding-модели,
    что и при обработке документов.
  </li>
  <li>
    <b>Поиск релевантных документов</b><br/>
    Выполняется поиск наиболее похожих текстовых фрагментов в <b>Qdrant DataBase</b>
    на основе косинусного сходства (или другой метрики).
  </li>
  <li>
    <b>Генерация ответа</b><br/>
    Найденные фрагменты передаются в <b>LLM</b> в качестве контекста, на основе которого
    модель генерирует итоговый ответ пользователю.
  </li>
</ol>

<h3>🧠 Интерпретация метрик</h3>

<p>
Полученные значения метрик показывают, что система уверенно справляется
с задачей поиска релевантного контекста и генерации фактически корректных ответов.
</p>

<ul>
  <li>
    <b>Высокая релевантность (0.81)</b><br/>
    Указывает на эффективную работу векторного поиска и качество embeddings —
    система в большинстве случаев находит документы, соответствующие вопросу.
  </li>

  <li>
    <b>Высокая фактическая точность (0.81)</b><br/>
    Генерируемые ответы в основном не содержат галлюцинаций и опираются
    на предоставленный контекст из базы документов.
  </li>

  <li>
    <b>Средняя Accuracy (0.68)</b><br/>
    Свидетельствует о том, что часть ответов хотя и релевантны,
    но могут быть недостаточно точными или сформулированными не оптимально
    с точки зрения пользователя.
  </li>

  <li>
    <b>Низкая полнота (0.57)</b><br/>
    Основная зона для улучшений. Ответы часто затрагивают суть вопроса,
    но не раскрывают его полностью. Потенциальные направления оптимизации:
    улучшение промптов, few-shot или использование chain-of-thought подходов.
  </li>
</ul>

<p>
В целом, метрики указывают на устойчивый и надежный RAG-пайплайн,
который уже демонстрирует хорошее качество, но имеет потенциал для роста,
особенно в части полноты и общей точности ответов.
</p>


<h2> Скрипты </h2>
<b> 1. Выгрузка постов </b>

Выполните следующую команду, находясь в корне репозитория:
```bash
export PYTHONPATH="${PWD}/src"
```

Затем оттуда же выполните:
```bash
python src/scripts/run_loader.py \
  --channel_id "id_канала" \
  --limit "количество_постов" \
  --offset "сколько_пропустить_постов" (опционально, по умолчанию 0)
```
Посты записываются батчами в месте запуска скрипта в csv файл
